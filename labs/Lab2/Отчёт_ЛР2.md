# Лабораторная работа № 2. Объектно-ориентированное программирование

**Вариант:** 3

**Проект:** CSharpLabs, .NET 10

**Исходное задание:** [lab2_charp.pdf](lab2_charp.pdf)

## Цель работы

Создать взаимодействующие классы C#, применить свойства, перегруженные конструкторы и `ToString()`, а также показать передачу объектов по ссылке. Вариант 3 включает задачи 1.3, 2.2, 2.3, 3.3, 4.5, 4.6 и 5.2. Они сгруппированы в пять пунктов меню по разделам задания.

## Структура решения

| Класс | Назначение |
| --- | --- |
| `PersonName` | Личное имя, необязательные фамилия и отчество; три способа создания. |
| `Person` | Человек с именем, ростом и необязательной ссылкой на отца; четыре конструктора. |
| `City` и `Route` | Город и ориентированный путь с положительной стоимостью. |
| `Cat` | Кот с методами `Meow()` и `Meow(int)`. |
| `Lab2` | Меню, ввод с клавиатуры и демонстрация всех задач. |

Каждый класс предметной области содержит явно реализованные свойства, конструктор и переопределение `ToString()`. Автосвойства, LINQ и лямбда-операторы не используются. Имена классов, полей, свойств и методов (кроме стандартного `ToString`) следуют [руководству Microsoft](https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/coding-conventions).

## Задание 1.3 — имена

`PersonName` хранит личное имя, фамилию и отчество в отдельных полях. При сборке строки пропущенные части не выводятся и лишние пробелы не появляются. Вводятся три человека из условия: Клеопатра, Пушкин Александр Сергеевич, Маяковский Владимир. Свойства отбрасывают пробелы по краям, пустое личное имя отклоняется.

Пример результата:

```text
Клеопатра
Пушкин Александр Сергеевич
Маяковский Владимир
```

## Задания 2.2 и 2.3 — человек с именем и отцом

`Person` использует объект `PersonName` вместо строки. Для задания 2.2 создаются люди с именами Клеопатра, Пушкин Александр Сергеевич и Маяковский Владимир, а также ростом 152, 167 и 189. Имена и рост вводятся с клавиатуры.

Для задания 2.3 создаются Иван Чудов, Пётр Чудов и Борис. Иван назначается отцом Петра, Пётр — отцом Бориса. При вызове `ToString()` отсутствующая фамилия берётся у отца, а отчество формируется по его личному имени. Сначала обновляется имя отца, поэтому Борис наследует фамилию через несколько поколений. Уже заданные фамилия и отчество сохраняются. Цикл в связях отцов отклоняется.

```text
Чудов Иван, рост: 175
Чудов Пётр Иванович, рост: 180
Чудов Борис Петрович, рост: 170
```

Рост в примере введён пользователем; условие его не фиксирует.

## Задание 3.3 — города

Объект `City` содержит название и список объектов `Route`. Ссылка в `Route` ведёт к другому объекту `City`, а не к копии его названия. По рисунку 2 созданы города A, B, C, D, E и F и ориентированные пути. Обратные направления добавлены отдельно там, где они показаны на схеме.

| Откуда | Куда и стоимость |
| --- | --- |
| A | B:5, F:1 |
| B | A:5 |
| C | B:3, D:4 |
| D | A:6, C:4, E:2 |
| E | — |
| F | B:1, E:2 |

После вывода заданной схемы пользователь вводит собственный путь. Программа проверяет название города, положительную стоимость, отсутствие пути в себя и отсутствие повторного пути.

## Задания 4.5 и 4.6 — перегруженные конструкторы

`PersonName` создаётся с одним, двумя или тремя параметрами. Общая инициализация находится в конструкторе с тремя параметрами. `Person` создаётся из строки либо объекта `PersonName`, с отцом или без; три конструктора делегируют основному. Таким образом присвоение полей выполняется в одном конструкторе каждого класса.

Показаны четыре имени из задания 4.5. У Христофора слово «Бонифатьевич» задано **фамилией**, как уточнено в условии; поэтому строковое представление имеет вид `Бонифатьевич Христофор`.

Показаны Лев (170), Сергей Пушкин (168) с отцом Львом и Александр (167) с отцом Сергеем:

```text
Лев, рост: 170
Пушкин Сергей Львович, рост: 168
Пушкин Александр Сергеевич, рост: 167
```

Также пользователь вводит имя и рост ещё одного человека; он создаётся конструктором со строковым именем и отцом.

## Задание 5.2 — кот мяукает

`Cat` хранит имя, выводит `кот: Имя`. Метод `Meow()` вызывает `Meow(1)`, а `Meow(int)` строит строку из заданного числа повторений через дефис. Вводятся имя кота и число повторений от 1 до 100. Для данных из условия:

```text
кот: Барсик
Барсик: мяу!
Барсик: мяу-мяу-мяу!
```

## Проверка ввода и тестирование

Меню принимает только существующие номера. Обязательные имена не могут быть пустыми; необязательные части имени можно пропустить клавишей Enter. Рост ограничен диапазоном 1–300, стоимость пути — 1–1 000 000, число мяуканий — 1–100. При неверном вводе поле запрашивается повторно. При завершении потока ввода программа корректно сообщает об этом и завершается.

| Проверка | Ожидаемый и полученный результат |
| --- | --- |
| Три имени из 1.3 | Пропущенные части имени не создают лишних пробелов. |
| Борис без фамилии и отчества | `Чудов Борис Петрович`. |
| Схема городов | Все шесть городов и десять направленных путей выведены. |
| Город `Z`, затем допустимый город | Ошибка ввода и повторный запрос. |
| Новый путь `A → C`, стоимость 5 | В строке A появляется `C:5`. |
| Рост `0`, затем `180` | Ошибка диапазона и повторный запрос; человек создан с ростом 180. |
| Кот Барсик, число повторений `0`, затем `3` | Ошибка диапазона, затем `Барсик: мяу-мяу-мяу!`. |

Проверено командой `dotnet build CSharpLabs.sln --no-restore`: **0 ошибок, 0 предупреждений**. Интерактивные сценарии пяти пунктов меню пройдены с автоматической подачей консольного ввода. Также проверено отсутствие автосвойств, LINQ и лямбд в новых файлах.
