# Лабораторная работа № 2. Объектно-ориентированное программирование

**Вариант:** 3

**Проект:** CSharpLabs, .NET 10

**Исходное задание:** [lab2_charp.pdf](lab2_charp.pdf)

## Цель работы

Создать взаимодействующие классы C#, применить свойства, перегруженные конструкторы и `ToString()`, а также показать передачу объектов по ссылке. Вариант 3 включает задачи 1.3, 2.2, 2.3, 3.3, 4.5, 4.6 и 5.2. Они сгруппированы в пять пунктов меню по разделам задания.

## Структура решения

Код разделён по папкам `CSharpLabs/Lab2/Task1_Names`, `Task2_People`, `Task3_Cities`, `Task4_Constructors` и `Task5_Cat` в порядке пунктов меню. `Lab2.cs` содержит меню. Общая проверка ввода вынесена в статический класс `ConsoleInput` рядом с точкой входа `Program`. Классы `PersonFullName` и `Person` повторно используются в четвёртом задании.

| Класс | Назначение |
| --- | --- |
| `PersonFullName` | Личное имя, необязательные фамилия и отчество; три способа создания. |
| `Person` | Человек с именем, ростом и необязательной ссылкой на отца; четыре конструктора. |
| `City` и `Route` | Город и ориентированный путь с положительной стоимостью. |
| `Cat` | Кот с методами `Meow()` и `Meow(int)`. |
| `Lab2` | Меню и вызов всех задач. |
| `ConsoleInput` | Проверка ввода номеров меню и управление терминальным выводом. |

Каждый класс предметной области содержит явно реализованные свойства, конструктор и переопределение `ToString()`. Автосвойства, LINQ и лямбда-операторы не используются. Имена классов, полей, свойств и методов (кроме стандартного `ToString`) следуют [руководству Microsoft](https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/coding-conventions).

## Задание 1.3 — имена

`PersonFullName` хранит личное имя, фамилию и отчество в отдельных полях. При сборке строки пропущенные части не выводятся и лишние пробелы не появляются. В коде создаются три объекта из условия: Клеопатра, Пушкин Александр Сергеевич, Маяковский Владимир. Свойства отбрасывают пробелы по краям, пустое личное имя отклоняется.

Пример результата:

```text
Клеопатра
Пушкин Александр Сергеевич
Маяковский Владимир
```

## Задания 2.2 и 2.3 — человек с именем и отцом

`Person` использует объект `PersonFullName` вместо строки. Для задания 2.2 создаются люди с именами Клеопатра, Пушкин Александр Сергеевич и Маяковский Владимир, а также ростом 152, 167 и 189. Их текстовые представления выводятся сразу при выборе задания.

Для задания 2.3 создаются Иван Чудов, Пётр Чудов и Борис. Иван назначается отцом Петра, Пётр — отцом Бориса. При вызове `ToString()` отсутствующая фамилия берётся у непосредственного отца, а отчество формируется по его личному имени. Уже заданные фамилия и отчество сохраняются. Назначить человека собственным отцом нельзя.

```text
Чудов Иван, рост: 175
Чудов Пётр Иванович, рост: 180
Чудов Борис Петрович, рост: 170
```

Для задания 2.3 рост в условии не задан; в демонстрации выбраны значения 175, 180 и 170.

## Задание 3.3 — города

Объект `City` содержит название и список объектов `Route`. Ссылка в `Route` ведёт к другому объекту `City`, а не к копии его названия. По рисунку 2 созданы города A, B, C, D, E и F и ориентированные пути. Обратные направления добавлены отдельно там, где они показаны на схеме.

| Откуда | Куда и стоимость |
| --- | --- |
| A | B:5, F:1, D:6 |
| B | A:5, C:3 |
| C | B:3, D:4 |
| D | A:6, C:4, E:2 |
| E | — |
| F | B:1, E:2 |

Схема создаётся из объектов `City` и `Route`. Метод добавления пути проверяет положительную стоимость, отсутствие пути в себя и отсутствие повторного пути.

## Задания 4.5 и 4.6 — перегруженные конструкторы

`PersonFullName` создаётся с одним, двумя или тремя параметрами. Общая инициализация находится в конструкторе с тремя параметрами. `Person` создаётся из строки либо объекта `PersonFullName`, с отцом или без; три конструктора делегируют основному. Таким образом присвоение полей выполняется в одном конструкторе каждого класса.

Показаны четыре имени из задания 4.5. У Христофора слово «Бонифатьевич» задано **фамилией**, как уточнено в условии; поэтому строковое представление имеет вид `Бонифатьевич Христофор`.

Показаны Лев (170), Сергей Пушкин (168) с отцом Львом и Александр (167) с отцом Сергеем:

```text
Лев, рост: 170
Пушкин Сергей Львович, рост: 168
Пушкин Александр Сергеевич, рост: 167
```

## Задание 5.2 — кот мяукает

`Cat` хранит имя, выводит `кот: Имя`. Метод `Meow()` вызывает `Meow(1)`, а `Meow(int)` строит строку из заданного числа повторений через дефис. В коде создаётся Барсик, который мяукает один и три раза. Результат из условия:

```text
кот: Барсик
Барсик: мяу!
Барсик: мяу-мяу-мяу!
```

## Проверка ввода и тестирование

Пункты 1–5 меню ЛР2 создают объекты с данными из условия и сразу показывают их вывод. В терминале экран очищается при переходе между меню, а результат задания остаётся виден до нажатия Enter. При перенаправлении ввода или вывода очистка и ожидание Enter отключены. Меню принимает только существующие номера; при ошибке номер запрашивается повторно. При завершении потока ввода программа сообщает об этом и завершается. Классы предметной области отклоняют пустые обязательные имена, неположительные рост и стоимость, а также число мяуканий вне диапазона 1–100.

| Проверка | Ожидаемый и полученный результат |
| --- | --- |
| Три имени из 1.3 | Пропущенные части имени не создают лишних пробелов. |
| Борис без фамилии и отчества | `Чудов Борис Петрович`. |
| Схема городов | Все шесть городов и двенадцать направленных путей выведены. |
| Задания 4.5 и 4.6 | Выведены четыре имени и три человека. |
| Кот Барсик | Выведены одно и три мяуканья. |
| Несуществующий номер пункта | Сообщение об ошибке и повторный запрос. |

Проверено командой `dotnet build CSharpLabs.sln --no-restore`: **0 ошибок, 0 предупреждений**. Проверен вывод всех пяти заданий и отклонение несуществующего номера меню. Также проверено отсутствие автосвойств, LINQ и лямбд в новых файлах.
